# PAGER — инвестиционная страница

Одностраничник для раннего раунда. Mobile-first, без зависимостей и сборки:
чистый HTML + CSS + vanilla JS.

```
pager-investor/
├── index.html          вся разметка + RU-тексты, EN в data-en
├── css/style.css       бенто-сетка, типографика, все карточки
├── js/app.js           i18n, появление карточек, счётчики, скрэмбл ID
├── assets/img/         оптимизированные медиа
└── serve.py            локальный статик-сервер для превью
```

Локальный просмотр:

```bash
python3 pager-investor/serve.py
```

Затем открыть `http://127.0.0.1:4321`. Деплой — выкладка папки как есть на любой
статик-хостинг. `serve.py` в продакшене не нужен.

## Формат: бенто

Страница собрана из карточек на 12-колоночной сетке. Одна карточка — один факт.
Инвестор сканирует, а не читает: ни один блок не требует прокрутки, чтобы понять,
о чём он.

Сетка адаптивная: 4 колонки на мобильном, 8 на планшете, 12 на десктопе.
Ширина карточки задаётся инлайн-переменными прямо в разметке:

```html
<article class="b ink" style="--d:7;--t:8">
```

`--d` — колонок на десктопе, `--t` — на планшете. Мобильный по умолчанию
на всю ширину; половинные карточки (`.chip`, `.step`, `.b-frame`) занимают 2 из 4.
Высота карточек не задаётся жёстко: строка выравнивается по самой высокой,
поэтому русский и английский тексты разной длины не ломают ряд.

**Каждый ряд должен добирать до 12.** Это единственное правило, которое легко
нарушить при правках: если сумма `--d` в ряду меньше 12, справа появится дыра.

## Типографика

Три роли, три гарнитуры.

**Дисплей — Roboto Condensed 900.** Узкий тяжёлый гротеск: именно он стоит
в hero-референсах из медиа-папки. Широкий Golos 900, стоявший тут раньше,
давал короткие «толстые» строки вместо плотного плаката — узкий помещает
17–19 знаков в строку при том же кегле. Всегда uppercase, tracking около
`-.01em` (узким начертаниям почти не нужен отрицательный трекинг),
интерлиньяж `.9`.

**Текст — Golos Text 400–700.** Лиды, карточки, списки. Тёплая, хорошо
нарисованная кириллица для чтения.

**Моно — JetBrains Mono 400/500.** Лейблы, номера секций, даты, PAGER ID,
сроки. Uppercase, tracking `.17em`, `tabular-nums`.

Два приёма поверх этого:

*Контраст веса внутри заголовка.* Первая часть набрана 700-м и приглушена,
вторая — 900-м, кегль один:

```html
<h2 class="h-sec"><i>Профиль решает,</i><br>что человеку доступно</h2>
```

Тег `<i>` переопределён — не курсив, а `font-weight:700` + `color:var(--mute)`.
Работает одинаково в русском и английском и переживает смену языка.

*Разрыв масштаба.* Между 10-пиксельным моно-лейблом и 190-пиксельной цифрой
нет промежуточных ступеней. Крупные числа и PAGER ID работают как графика.

| Роль | Класс | Кегль |
|---|---|---|
| Манифест | `.mnf` | моб. `clamp(31px, 7.8vw, 80px)` · десктоп `clamp(40px, 3.7vw, 66px)` |
| Заголовок блока | `.h-sec` | `clamp(30px, 5.2vw, 74px)` |
| Крупное число | `.mega-num` | `clamp(86px, 13vw, 190px)` |
| PAGER ID | `.mega` | `clamp(38px, 8.6vw, 124px)` |
| Номер секции (фоновый) | `.head-n` | `clamp(88px, 15vw, 230px)`, opacity `.055` |
| Лейбл | `.tag` | 10–11px, tracking `.17em` |

Кегль манифеста на десктопе подобран под ширину колонки так, чтобы каждый
куплет лёг в одну строку. При правке текста это первое, что стоит проверить.

## Палитра

| Токен | HEX | Роль |
|---|---|---|
| `--board` | `#E3DFD7` | фон доски — темнее карточек, чтобы те читались |
| `--paper` | `#F3F0EA` | светлая карточка |
| `--ink` | `#0A0A0B` | тёмная карточка |
| `--mist` | `#C4D6F0` | тонированная карточка (акцент приложения) |
| `--steel` | `#A8BEDD` | тонированная карточка (акцент приложения) |

Цвета профилей — Личное `#20C997`, Работа `#38BDF8`, Гость `#D4C4B7`,
Альтер эго `#FFCE7A` — используются только там, где продукт показывает
четыре вещи одновременно: аватары мультипрофиля, полосы карточек профилей
и столбцы матрицы возможностей. Нигде больше: иначе четыре цвета превращаются
в шум.

## Структура

| # | Блок | Карточки |
|---|---|---|
| — | Hero | светлый плейт во всю карточку + манифест · боковая колонка: PAGER ID, Q3 2026, Q1 2027 |
| 01 | PAGER ID | крупный ID (7) + четыре факта (5) · продуктовый шот (5) + Premium ID (7) |
| 02 | Мультипрофиль | четыре аватара (5) + коллапс контекста (7) · четыре рендера (3×4) |
| 03 | Профили общения | четыре чипа (3×4) · матрица возможностей (8) + реальный экран (4) |
| 04 | Временные контакты | «24» (4) + сценарий (8) · четыре шага (3×4) · сценарии (12) |
| 05 | Статус | «13» и список (5) + «5» в разработке (4) + экран (3) · milestone (12) |
| 06 | Бизнес-модель | B2C (6) + B2B (6) · последовательность (12) |
| 07 | Roadmap | «Сейчас» (12) · четыре квартала (3×4) |
| 08 | Раунд | запрос и CTA (7) + направления средств (5) · milestone (12) · основатель (12) |

Порядок 02 и 03 отличается от ТЗ намеренно: мультипрофиль — слой идентичности
(имя, фото, описание), профили общения — слой разрешений поверх него.
Нарратив: **находят** (PAGER ID) → **видят таким** (мультипрофиль) →
**могут вот это** (профили) → **на сколько** (24 часа).

### Матрица возможностей

Ядро блока 03. Девять строк (текст, аудио- и видеосообщения, аудио- и
видеозвонки, группы, пересылка, видимость статуса, срок связи) на четыре
столбца профилей. Заполненная точка в цвете профиля — разрешено, контур — нет.
Заменяет четыре почти одинаковых списка тумблеров: сравнение считывается
за пару секунд.

## Тексты и языки

Русский лежит в разметке, английский — в атрибуте `data-en` на том же узле.
Переключатель RU/EN меняет `innerHTML`, поэтому оба варианта могут содержать
`<i>` и `<br>` — разметка смешанного веса переживает смену языка.

Добавить строку: русский текст в узел, английский — в `data-en`.

## Что сознательно не сделано (пометки «без публикации» из ТЗ)

- PAGER ID не подан как «username вместо телефона» — показан как точка входа,
  которая безопаснее номера и проще сложного ника.
- Premium ID — будущий слой монетизации, не главное преимущество.
- Блок профилей говорит только про разрешения; имена и фото живут
  в мультипрофиле.
- Нет формулировок «разные версии вас», «смена личности», «маски».
- «24 часа» подано как характеристика продукта, а не статистика. Про удаление
  переписки не обещано ничего — только «завершить связь».
- B2C и B2B разведены по этапам.
- Roadmap показывает продуктовые результаты, а не список функций.

## Что заменить перед публикацией

- `hello@pager.app` в CTA и футере — на реальный адрес или форму.
- `og:image` — на отрисованную превью-картинку 1200×630.
- Даты в roadmap — обновлять при любом сдвиге сроков.
